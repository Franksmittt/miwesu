================================================================================
1. WHAT THIS PROJECT IS
================================================================================

A production-oriented marketing + operations web application for MIWESU GAME
FARM ("Iron Eden"): a private luxury sanctuary in the Makoppa district near
Thabazimbi, Limpopo, South Africa (Waterberg, malaria-free bushveld).

Public site:
  - Two exclusive-use residences (Homestead ~16 sleepers, Rooibok Kraal / Stone
    Villa ~6 sleepers), activities, conservation story, species hunting guides,
    gallery (Facebook folder under public/images/Facebook), blog ("Hunter's
    Journal"), tools (SAPS 520, biltong calculator), wood products, partners,
    trophy export guidance.
  - Booking is enquiry-first (no public checkout for lodge stays); public rates
    are presented as "on request" where configured.

Admin / backend:
  - Password-gated admin: bookings CRM, calendar, rates manager, pricelist PDF,
    email diagnostics. Prisma + PostgreSQL (e.g. Supabase). Resend for outbound
    mail. Invoice PDF and SAPS 520 PDF generation. Stripe present in codebase
    but not the primary lodge enquiry flow.

Locale:
  - Primary English site; dedicated landing routes /de and /es for international
    reach with hreflang from root metadata.

6. SEO — WHAT THE SITE DOES (AND RECENT COPY ALIGNMENT)
================================================================================

Canonicals and base URL
  - NEXT_PUBLIC_BASE_URL (default https://www.miwesu.co.za) drives absolute
    URLs. lib/seo.ts constructCanonicalUrl() builds consistent canonicals
    (no trailing slash except root).

Metadata surfaces
  - Per-route or per-segment Metadata in App Router layouts/pages: title,
    description, keywords where used, alternates.canonical, openGraph and
    twitter via generateOpenGraph / generateTwitterCard.
  - Open Graph images are centralised in lib/open-graph.ts (marketingOgAbsolute)
    so key templates get appropriate hero/OG art.

International
  - Root metadata alternates.languages: en-GB, de, es, x-default for hreflang.
  - German and Spanish landing routes (/de, /es) mirror core positioning;
    species count and similar phrases use "14+" wording in EN/DE/ES so search
    snippets do not read as "exactly fourteen animals only."

Structured data (JSON-LD)
  - Organization, WebSite, LodgingBusiness (local lodge entity with geo and
    amenities) on the home narrative.
  - Species: WebPage with biological alignment — Taxon (schema.org) with
    sameAs to Wikidata/Wikipedia where configured; richer "power" graph on
    wildlife species pages combining WebPage + Taxon + Product/Offer for
    enquiry-led hunts (generateSpeciesPowerPageJsonLd in lib/seo.ts).
  - FAQPage (standalone FAQ + nested home FAQ graph), Article/BlogPosting on
    posts, BreadcrumbList on many layouts, WebPage schema on marketing layouts,
    compare page handling for query pairs, gallery ItemList (image URLs from
    Facebook folder when present, else curated list), TouristTrip on activities,
    Product samples where rates/tools warrant it, wood commerce graph where used.
  - Components under components/StructuredData.tsx emit the above from layout
    wrappers.

Discovery
  - app/sitemap.ts lists static routes, blog slugs, and all SPECIES_SLUGS.
  - robots.txt (app/robots.ts) allows the public site and blocks /admin and
    /api in production.

Content signals (E-E-A-T)
  - Species pages tie common names to scientific names and authoritative
    sameAs links. Blog and conservation copy support topical depth.

This overview does not replace ongoing SEO work (Search Console, Core Web
Vitals, content updates); it documents what the codebase implements.

7. BUILD & QUALITY
================================================================================

Commands:
  npm run dev      — local development
  npm run build    — prisma generate + next build (used for Vercel)
  npm run lint     — Next.js ESLint
  npm run lighthouse — optional CWV/SEO audit script (local URL)

The codebase is intended to ship: TypeScript checking runs on build; keep
environment variables set in Vercel (or host) for production.

If Next.js reports a missing webpack chunk after interrupted builds, delete the
.local .next folder and run npm run build again.
